Three cohesive Swift files form the keyboard engine layer:
- `InputMethod.swift` defines the `InputMethodType` enum (Telex, VNI, VIQR, Simple Telex) used to configure the underlying engine.
- `SKeyEngine.swift` is the hot-path wrapper around the Rust `skey_engine_*` C API. It owns an `OpaquePointer` to the native engine, configures it via `setupDefaultOptions()` (charset XUTF8, free marking, IME mode, etc.), exposes typed setters (`setModernStyle`, `setFreeMarking`, `setQuickTelex`, …) that read-modify-write `SKeyOptions`, and processes keystrokes through `filter(character:)` / `backspace()` returning a `ProcessResult`. A private `withEngine` helper serializes access with an `os_unfair_lock` and zero-heap UTF-8 output extraction uses `withUnsafeTemporaryAllocation` to avoid heap allocations on the hot path.
- `MacroEngine.swift` is a separate, thread-safe singleton (`shared`) implementing in-memory shortcut expansion. It tracks the current word buffer, matches against a `macroMap` keyed by lowercased shortcuts loaded from `AppSettings.shared.macro.items`, and on space emits a `MacroMatchResult` indicating how many backspaces to perform and what replacement text to insert (with optional auto-caps transformation).
Dependency direction: both engines depend only on Foundation and the external Rust bridge; `MacroEngine` reads settings but does not call `SKeyEngine`, keeping macro expansion decoupled from the core filter pipeline.
