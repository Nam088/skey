- Navigation state is centralized in the singleton `SettingsNavigationState.shared` and mutated through `navigate(to:subTab:)`, which updates both the active tab and the corresponding per-tab sub-tab index while clearing search text.
- Each settings tab is implemented as a SwiftUI `View` struct that binds to `@ObservedObject AppSettings.shared.<domain>` (e.g. `keyboard`, `macro`, `shortcuts`) and triggers side effects via managers like `EventTapManager.shared` when values change.
- Reusable UI building blocks are extracted into `UI/Components/SettingsComponents.swift` — `SubTabBar`, `SettingsGroup`, `SettingsRow`, `KeyCapBadge` — and composed by every tab view instead of being duplicated inline.
- All user-facing strings go through the `L10n(...)` localization helper rather than hard-coded literals, applied uniformly to tab titles, subtitles, row labels, and search item metadata.
- Searchability is achieved by registering each setting as a `SettingSearchItem` in `SettingsNavigationState.allSearchItems` with `tab`, `subTab`, `icon`, and comma-separated `keywordsKey`, then filtering via `search(query:)` against title, subtitle, keywords, and sub-tab titles.
- Tab definitions live in the `MainTab` enum (with `CaseIterable`, `Identifiable`, localized `title`/`subtitle`, SF Symbol `icon`, and `badgeColor`) so the sidebar list and the detail switch can derive their presentation from a single source.
