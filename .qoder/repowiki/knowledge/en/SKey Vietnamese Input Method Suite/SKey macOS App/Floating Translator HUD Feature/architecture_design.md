The feature is organized into three layers under `Sources/Features/Translator/`:
- `Models/TranslationEngine.swift` defines the domain types: `TranslationEngineType` (an enum over Google, Apple, Gemini, DeepL, Groq with display metadata like icon, badge color, free-key status) and `TranslationEngineConfig` (per-engine enablement + API key), plus a default engine list.
- `Services/TranslationService.swift` is a singleton `ObservableObject` that orchestrates translation via a cascade: it iterates user-enabled engines in priority order, calls the matching private async method per engine (`translateWithGoogle`, `translateWithGemini`, `translateWithDeepL`, `translateWithGroq`), records latency, and falls back to Google NMT as a universal safety net when all configured engines fail. Each engine implementation uses a shared `URLSession` with explicit timeouts and parses responses (HTML scraping for Google Mobile, JSON for DeepL/Gemini/Groq).
- `UI/TranslationHUDController.swift` owns a custom `NSPanel` subclass (`TranslationHUDPanel`) configured as a borderless floating window above other apps, and exposes a `shared` singleton with `toggleHUD(show:)` / `hideHUD()` entry points, ESC-key dismissal via an `NSEvent` local monitor, and mouse-positioned placement.
- `UI/TranslationHUDView.swift` is the SwiftUI content hosted inside the panel, binding to `AppSettings.shared.translator` for engine settings, driving `TranslationService.shared.translate(...)` on a background `Task`, and rendering source/target language pickers, a paste/clear toolbar, and an output section showing the active engine badge and copy-to-clipboard action.
Dependency direction is strictly UI → Service → Models; the service depends only on Foundation/AppKit networking and reads engine configuration from `AppSettings` (external).
