Two sibling sub-projects with distinct roles:
- `src/gui/` builds the standalone `unikey` binary (declared in `Makefile.am`). It is a C program composed of `gui.c` (X11 window/event loop), `guiopt.c` (parsing GUI option files into `UkGuiOpt`), and `uksync.c` (charset/method conversion between UniKey and external sync protocols, plus X property access via `Atom` helpers). Cross-cutting constants for charsets (`UNIKEY_UTF8`, `UNIKEY_VIQR`, `UNIKEY_TCVN`, `UNIKEY_VNI`) and input methods are declared in `gui.h` and duplicated in `uksync.h`; `xvnkb.h` supplies XIM-related types. The GUI links against `-lX11` and reuses `../xim/optparse.{c,h}` for command-line parsing.
- `src/ukinterface/` builds a non-installed static library `libukint.la` that wraps the core engine (`../ukengine/libUnikey.la`) behind a C-compatible API exposed by `unikey.h`. The header documents a strict lifecycle: `UnikeySetup` → optional `UnikeySetInputMethod`/`UnikeySetOutputCharset`/`UnikeySetOptions` → per-keypress `UnikeyFilter` reading globals like `UnikeyBufChars`/`UnikeyBackspaces`/`UnikeyAnsiBuf` → `UnikeyCleanup`. The wrapper is compiled as C++ but exposes an `extern "C"` interface so the C GUI can call it.
Dependency direction: `gui` depends on `ukinterface` (via the shared engine) and on X11; `ukinterface` depends only on the core engine and encoding libraries (`../ukengine`, `../vnconv`, `../byteio`). There is no reverse dependency — the engine has no knowledge of the GUI.
