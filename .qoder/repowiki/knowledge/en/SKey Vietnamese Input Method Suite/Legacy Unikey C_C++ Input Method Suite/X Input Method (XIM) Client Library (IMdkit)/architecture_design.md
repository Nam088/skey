Built as a single autotools `noinst_LTLIBRARIES` target `libIMdkit.la` (see `Makefile.am`) that bundles all sources into one static/shared library consumed by higher-level IM modules. The code is organized around the public `IMdkit.h` API surface, with internal headers `Xi18n.h`, `Xi18nTr.h`, `Xi18nX.h`, `XimProto.h`, `XimFunc.h`, and `Xtrans.h` defining the XIM wire protocol, transport abstraction, and X-specific glue. Core layers: (1) Transport layer (`i18nTr.c`, `Xtrans.h`) opens/accepts connections via `_XimdXTransOpenCOTSServer` and reads/writes raw bytes through `TransRead`/`TransWrite`; (2) Protocol framing layer (`FrameMgr.c` + `i18nPtHdr.*`) serializes/deserializes XIM packets using declarative `XimFrameRec` templates and byte-swap-aware token readers; (3) Connection/session layer (`IMConn.c`, `i18nIc.c`) manages `Xi18nClient` chains, connect IDs, and input contexts; (4) Attribute/value marshalling (`i18nAttr.c`, `IMValues.c`, `i18nMethod.c`, `i18nClbk.c`) handles `XIMAttribute`/`XICAttribute` lists, hotkey triggers, and callback dispatch; (5) X-specific helpers (`i18nX.c`, `i18nUtil.c`) bridge to Xlib/Xt. Dependency direction flows outward from `FrameMgr` → `i18n*` modules → `IMdkit.h` consumers; protocol constants are centralized in `XimProto.h` and `Xi18n.h`. A sample IM (`doc/Xi18n_sample/`) demonstrates how an external IM server implements the same wire protocol.
