The repository is organized as three sibling subsystems sharing one input-engine contract: `src/` holds the original C++ UniKey reference implementation used as the ground-truth; `port/` is a Cargo workspace that re-implements the same engine in safe `no_std` Rust (`skey-core`) and exposes it through a C ABI (`skey-capi`, producing `libskey.a`); `macos/skey-app/` is an AppKit/SwiftUI menu-bar application that links against `libskey.a` to process keystrokes via EventTap. The `difftest` crate in `port/` drives the Rust engine and the C++ reference side-by-side to validate behavioral parity, making the C++ sources the canonical specification for the Rust port. Build orchestration lives per-subsystem (autotools for `src/`, `cargo build --workspace` for `port/`, and `macos/skey-app/build.sh` which compiles `libskey.a` then builds and signs `SKey.app`), so the root acts as a project index rather than a single build entry point.
