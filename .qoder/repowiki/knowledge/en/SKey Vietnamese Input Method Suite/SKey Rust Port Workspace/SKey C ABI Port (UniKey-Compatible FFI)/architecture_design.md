Single Rust crate (`skey-capi`) compiled as `cdylib`/`staticlib`/`rlib` whose only dependency is `skey-core` (with default features disabled, `alloc` enabled). The module is organized into three logical layers inside `src/lib.rs`:
- Legacy process-global layer: a `Global<T>` wrapper around `UnsafeCell<T>` exposes `#[no_mangle]` mutable globals (`UnikeyBuf`, `UnikeyBackspaces`, `UnikeyBufChars`, `UnikeyOutput`, plus a single `Engine` instance) so existing front ends link against unchanged symbols.
- Context-based layer: an opaque `UnikeyEngine` handle with `create`/`free` lifecycle and per-instance methods mirroring every legacy function, enabling multi-session and thread-safe usage without shared state.
- Extension layer: additional options (`swallowed_key_restore`, quick-telex, quick consonant shortcuts, upper-case first char, allow consonant ZFWJ) exposed via dedicated setter/getter pairs to avoid growing the ABI-stable `UnikeyOptions` struct.

The `include/skey.h` header declares the new `SKey*` API and aliases all `unikey_*` symbols to them; `include/unikey.h` declares the original `Unikey*` symbols plus the context API and extensions. All FFI boundaries are in this crate — `skey-core` itself contains no `unsafe` and forbids it, so unsafe lives exclusively here to bridge C ABI expectations (raw pointers, mutable globals, `repr(C)` structs) onto safe Rust types.
