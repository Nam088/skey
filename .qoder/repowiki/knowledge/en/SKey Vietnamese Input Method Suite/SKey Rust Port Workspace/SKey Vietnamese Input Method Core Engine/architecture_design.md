The crate is organised as a flat library (`lib.rs` re-exports `Engine`, `Edit`, `Options`, `OutputType`) with four primary domain packages plus shared infrastructure. The `engine` module owns the central `Engine` struct — a fixed-size state machine backed by `[WordInfo; MAX_UK_ENGINE]` buffers — whose `key()` method dispatches a `KeyEvent` through `dispatch_inner` into handlers for roof, hook, tone, telex, map, escape, or append paths (implemented in `append.rs`, `transform.rs`, `shortcuts.rs`). `input/mod.rs` provides an `InputProcessor` that maps raw key codes to events using per-method lookup tables (Telex, VNI, VIQR, MSVI, Simple Telex, user) and classifies characters via `UKC_MAP`. `phonetics/` contains the linguistic layer: `lexi` defines `Lexi`, `VSeq`, `CSeq` symbols; `tables` holds the large transition tables; `rules` exposes validity checks (`is_valid_cv`, `is_valid_vc`, …); `seq` and `lexi_consts` hold sequence data. `charset/` encodes output bytes according to the selected charset; `out.rs` defines a `Sink` trait and an `OutBuf` that mirrors the original C++ `StringBOStream` (including its off-by-one size reporting). Optional `extensions/` adds macro tables, user keymaps, English word restoration, quick shortcuts, and enwords — all gated behind the `alloc` feature so the keystroke path remains allocation-free. The crate is compiled with `#![forbid(unsafe_code)]` and `#![cfg_attr(not(test), no_std)]`; only `alloc`-gated features use heap.
