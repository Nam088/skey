The workspace is organized as three sibling subsystems bound by one input-engine contract: `src/` holds the original C/C++ UniKey reference implementation used as ground truth; `port/` is a Cargo workspace that re-implements the same engine in safe `no_std` Rust (`skey-core`) and exposes it through an explicit C ABI crate (`skey-capi`, producing `libskey.a`); `macos/skey-app/` is an AppKit/SwiftUI menu-bar application that links against `libskey.a` to process keystrokes via EventTap. The `difftest` crate in `port/` drives both the Rust engine and the C++ reference side-by-side to validate behavioral parity, making the C++ sources the canonical specification for the Rust port. Build orchestration lives per-subsystem (autotools for `src/`, `cargo build --workspace` for `port/`, and `macos/skey-app/build.sh` which compiles `libskey.a` then builds and signs `SKey.app`), so the root acts as a project index rather than a single build entry point.
