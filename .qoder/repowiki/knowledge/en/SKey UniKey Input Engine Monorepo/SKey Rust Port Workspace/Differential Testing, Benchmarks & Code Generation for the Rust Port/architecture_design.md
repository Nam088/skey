Four cooperating sub-trees under `port/` form a self-contained verification harness around the Rust port of UniKey:

- `difftest/` — A Cargo binary (`src/main.rs`, depends on `skey-core`) that implements the same stdin protocol as `oracle/oracle.cpp` (commands `K/B/R/S/C/L/U/T/Z/-`), plus special subcommands `gen`, `type`, `bench`, and `hashes`. It is invoked by Python sweepers (`sweep.py`, `ctxsweep.py`, `keymapsweep.py`, `macrosweep.py`, `quicksweep.py`, `soak.py`) which spawn both the oracle and the Rust binary with identical option matrices and compare their line-by-line trace output, failing fast on the first divergence.
- `oracle/` — The canonical reference implementation. `oracle.cpp` drives the original C++ engine via `unikey.h`/`ukengine.h` and emits deterministic per-keystroke traces; it is compiled twice: once linking the real C++ engine, and once with `RUST_BACKEND` defined so it calls exported C ABI helpers over the Rust library, making the ABI itself testable. `ctx_harness.c` provides an additional context-level harness.
- `bench/` — A C++ in-process benchmark (`bench.cpp`) that mirrors the Rust `bench` subcommand exactly (same corpus file, command mix, warm-up passes, round count) so `compare.py` can interleave runs of `bench_cpp` / `bench_cpp_o3` against `difftest bench` and report ns/key and M keys/s ratios across input-method × charset configurations.
- `tablegen/` — Source-of-truth code generation. `dump.cpp` links against the original engine headers (`keycons.h`, `vnlexi.h`, `inputproc.h`, `charset.h`) and emits Rust source files (`tables.rs`, `lexi_consts.rs`) containing static lookup tables, key maps, and lexeme constants so the Rust port cannot drift from the C++ data. `gen_lexi.py` parses `src/ukengine/vnlexi.h` enums to regenerate those constants, with compile-time assertions in `lexi.rs` catching mismatches.

Dependency direction is one-way: Python harnesses → (C++ oracle | Rust difftest); tablegen reads C++ headers and writes Rust sources consumed by the main crate; benchmarks read the same corpus but do not depend on each other.
