Three cohesive Swift files form the keyboard engine layer with a clear dependency direction into Foundation and an external Rust C bridge:
- `InputMethod.swift` declares the `InputMethodType` enum (Telex, VNI, VIQR, Simple Telex) that configures the underlying engine via raw values.
- `SKeyEngine.swift` is the hot-path wrapper owning an `OpaquePointer` to the native engine. It initializes the engine in `init`, applies default options (`setupDefaultOptions` sets charset XUTF8, free marking, IME mode, etc.), exposes typed setters (`setModernStyle`, `setFreeMarking`, `setQuickTelex`, …) that read-modify-write `SKeyOptions`, and processes keystrokes through `filter(character:)` / `backspace()` returning a `ProcessResult`. A private `withEngine` helper serializes all access with an `os_unfair_lock` and guards against a nil pointer; `readResult` uses `withUnsafeTemporaryAllocation` to extract UTF-8 output on the stack, avoiding heap allocations on the hot path.
- `MacroEngine.swift` is a separate thread-safe singleton (`shared`) implementing in-memory shortcut expansion. It tracks a bounded `currentWord` buffer, matches against a `macroMap` keyed by lowercased shortcuts loaded from `AppSettings.shared.macro.items`, and on space emits a `MacroMatchResult` indicating how many backspaces to perform and what replacement text to insert (with optional auto-caps transformation).
Dependency direction: both engines depend only on Foundation and the external Rust bridge; `MacroEngine` reads settings but does not call `SKeyEngine`, keeping macro expansion decoupled from the core filter pipeline.
