The module is organized as a classic SwiftUI feature layer inside `macos/skey-app/Sources/Features/Settings/`. `SettingsWindowController` (AppKit `NSWindowController`) is the single entry point that instantiates an `NSWindow`, wraps a `NSVisualEffectView` + `NSHostingView`, and owns a singleton `SettingsNavigationState` used to drive navigation. `SettingsDashboardView` renders a `NavigationSplitView` with a sidebar of `MainTab` entries plus a search bar; the detail pane switches on `selectedTab` to render one of seven tab views under `UI/Tabs/`. Each tab view (`KeyboardSettingsTab`, `ClipboardSettingsTab`, etc.) manages its own sub-tabs via `SubTabBar` from `UI/Components/SettingsComponents.swift`, which also provides reusable `SettingsGroup`, `SettingsRow`, and `KeyCapBadge` components. Cross-cutting state lives in `SettingsNavigationState`, a Combine `ObservableObject` that publishes `selectedTab`, per-tab sub-tab indices, and `searchText`, and exposes `navigate(to:subTab:)` plus a centralized `allSearchItems` registry of `SettingSearchItem` records that map every setting to a tab/subTab pair for unified search. Tab views bind directly to shared domain models via `@ObservedObject AppSettings.shared.*` (keyboard, macro, shortcuts, etc.), keeping this feature layer purely presentational and dependent only on those app-wide settings services.
