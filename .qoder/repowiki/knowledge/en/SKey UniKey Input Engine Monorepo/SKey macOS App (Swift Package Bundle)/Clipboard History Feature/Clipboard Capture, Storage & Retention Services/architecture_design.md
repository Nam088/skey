The module is organized around a central `ClipboardStore` actor that orchestrates three collaborator abstractions: a `ClipboardRepository` protocol (implemented by `SQLiteClipboardRepository` using the C `sqlite3` API with WAL mode and a dedicated serial queue, plus an in-memory fallback), a `PayloadStoring` protocol backed by `FileSystemPayloadStore` for large payloads under Application Support, and a `ClipboardRetentionPolicy` struct that decides whether to skip, bump, retain full, or retain metadata-only based on pasteboard type markers, bundle exclusions, regex patterns, duplicate hashes, and size limits. `ClipboardMonitor` polls `NSPasteboard.changeCount` on a timer, classifies captured content into `CapturedClipboardContent` (plain text, rich text, image, file reference) with SHA-256 hashing, and forwards it to `ClipboardStore.capture`. Search results are ranked by `SearchRanking`, which scores exact substring, normalized (diacritic-insensitive via `vietnameseFold`), and subsequence matches. The store maintains an in-memory cache of `ClipboardItem`s, emits `ClipboardEvent` values through an `AsyncStream`, and prunes excess unpinned items according to the configured history limit.
