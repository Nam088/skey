The module is organized as a layered conversion engine built around the `VnCharset` abstract base class in `charset.h`, which defines `nextInput`/`putChar`/`startInput`/`startOutput` for streaming byte-in to standard-character to byte-out translation. Concrete subclasses implement specific encodings: `SingleByteCharset` (TCVN3/VISCII/BKHCM1/VIETWAREF/ISC), `DoubleByteCharset` (VNIWIN/BKHCM2/VIETWAREX/VNIMAC), `UnicodeCharset` plus `UnicodeUTF8Charset`, `UnicodeRefCharset`/`UnicodeHexCharset`, `UnicodeCStringCharset`, `WinCP1258Charset`, `UnicodeCompCharset`, `VIQRCharset`, and `UTF8VIQRCharset`. A singleton `CVnCharsetLib` (`VnCharsetLibObj`) owns all charset instances and exposes them through `getVnCharset(int)` keyed by the `CONV_CHARSET_*` constants declared in `vnconv.h`. The core loop lives in `convert.cpp`'s `genConvert`, which reads bytes via an input charset, applies global options (upper/lower/remove tone) from `VnConvOptions`, then writes via the output charset; `VnConvert` wraps this with `StringBIStream`/`StringBOStream`, and `VnFileConvert` handles file I/O with a temporary-file rename strategy on Windows. `pattern.{h,cpp}` provides a KMP-style `PatternState`/`PatternList` used by VIQR escaping logic. Data tables mapping each encoding to a common internal `StdVnChar` space are declared in `data.h` and defined elsewhere. The public C API (`VnConvert`, `VnFileConvert`, `VnConvErrMsg`, `VnConvSet/Get/ResetOptions`) is exported via `DllInterface` macros that resolve to `__declspec(dllexport/dllimport)` on MSVC and no-op otherwise, enabling both DLL and static-library builds.
