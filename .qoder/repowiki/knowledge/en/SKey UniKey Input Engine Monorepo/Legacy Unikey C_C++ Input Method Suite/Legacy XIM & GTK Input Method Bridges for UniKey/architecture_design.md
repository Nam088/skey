Two parallel input-method front-ends share the same underlying `unikey.h` / `vnconv.h` engine but expose it through different platform APIs.

- `src/xim/` implements a standalone XIM server process (`xim.c`) built on Sun's IMdkit (`IMdkit.h`, `Xi18n.h`). It registers an `XIMS` with `XOpenIM`, declares supported styles (`XIMPreeditNothing|XIMStatusNothing`) and trigger keys, then dispatches key events through per-input-context objects defined in `IC.h`/`IC.c` (struct `_IC` holding client window, focus window, preedit/status attributes). The server communicates with the GUI keyboard via X atoms (`AIMCharset`, `AGUIVisible`, etc.) and uses `uksync.c` to translate between UniKey and sync modes. Supporting utilities include `ukopt.c` (option parsing), `optparse.*` (generic option parser), `trigger.c`/`test.c`/`parse-test.c` (tests), and `install.sed`/`uninstall.sed`/`install.sh` for packaging.
- `src/unikey-gtk/` provides a GTK+ IM module (`imvn.c`) exporting the `unikey` context ID via `GtkIMContextInfo`, which instantiates `GtkIMContextVn` from `gtkimcontextvn.c`/`gtkimcontextvn.h`. This subclass of `GtkIMContext` intercepts key events through `filter_key`, maps shortcuts (e.g. Alt+Shift switch, Ctrl+Shift+F1..F9) via a `ShortcutInfo[]` table, and reuses the same `UkXimOpt GlobalOpt`, `uksync.*` translation layer, and `../gui/xvnkb.h` GUI bridge as the XIM side so both front-ends stay in sync.
- Dependency direction is one-way: both front-ends depend on shared core headers (`unikey.h`, `vnconv.h`, `xvnkb.h`) and each other's `uksync`/`ukopt` interfaces; the GTK side includes `../xim/ukopt.h` directly, while the XIM side does not depend on GTK.
